# غيث — نظام محاسبي بسيط

واجهة عربية باتجاه RTL لنشاط تعليمي واحد، وعملة أساسية SAR. React + Vite، مع PostgreSQL وتخزين خاص للمرفقات على Supabase.

## التشغيل

Node.js 22 أو أحدث:

```sh
npm ci
npm run dev
```

بدون إعدادات Supabase، تظهر نسخة تجريبية واضحة تحفظ البيانات في Local Storage داخل المتصفح فقط، ولا تسمح برفع المرفقات. هذه النسخة ليست تخزينًا مشتركًا ولا تحتوي بيانات افتتاحية مالية وهمية.

```sh
npm test
npm run build
```

## ربط التخزين المشترك

1. أنشئ مشروع Supabase مجانيًا وشغّل `supabase/schema.sql` مرة واحدة في SQL Editor.
2. من Authentication أنشئ المستخدم `ghaith@ghaith.local` بكلمة المرور المطلوبة، وأكد بريده من لوحة التحكم. لا تضع كلمة المرور في الكود أو Git. اسم الدخول في الواجهة `ghaith` يتحول داخليًا لهذا البريد.
3. انسخ UUID المستخدم من لوحة Authentication وأضفه إلى جدول `accounting_members` باستخدام SQL Editor:

```sql
insert into public.accounting_members(user_id) values ('UUID-FROM-AUTH');
```

4. عطّل إنشاء حسابات جديدة في Authentication. المستخدم المصرح له فقط يستطيع الوصول بفضل RLS وقائمة العضوية، حتى لو عُرف مفتاح الواجهة العام.
5. انسخ `.env.example` إلى `.env.local` وضع رابط المشروع ومفتاحه العام anon/publishable. لا تستخدم service_role أو أي مفتاح سري في متغيرات `VITE_`.
6. أعد تشغيل Vite، أو أعد البناء للنشر. سجّل الدخول باسم `ghaith`. جميع الأجهزة تستخدم الحساب نفسه.

حفظ القيد يتحقق من التوازن على المتصفح والخادم، ويُنفذ كعملية ذرية. تعارض الكتابة من جهازين يُرفض ويُحدّث البيانات بدل الكتابة فوق تغييرات الآخر. النسخة الأولى مناسبة لحجم بيانات شخصي صغير؛ تحتفظ بالحالة داخل صف JSONB واحد لتبسيط التشغيل، ويُفضل التحويل لجداول مستقلة عند التوسع. التقارير تستخدم هللات صحيحة لتجنب أخطاء الكسور. القيود المحفوظة لا تُعدّل ولا تُحذف؛ التصحيح بقيد عكسي جديد. تعديل أسماء الحسابات ومراكز التكلفة متاح، وحذف المرتبط بحركات ممنوع.

## نشر مجاني على Cloudflare Pages

اربط المستودع بـCloudflare Pages، أمر البناء `npm run build` ومجلد الناتج `dist`، وأضف متغيري Supabase أعلاه في إعدادات البناء. رابط `pages.dev` يكفي دون شراء نطاق. لا يحتاج التطبيق خادم Node مستمرًا؛ Supabase ينفذ حفظ البيانات والمصادقة والتخزين. حدود الخطط المجانية وتوفر الخدمة تخضع لشروط مقدميها الحالية؛ لم يتم نشر التطبيق تلقائيًا.

## المرفقات والتقارير

مرفقات PDF وJPEG وPNG وWebP حتى 5MB للملف، داخل bucket خاص. الروابط الموقعة صالحة لمدة 60 ثانية. يُنصح بضغط الصور لتقليل استهلاك الخطة المجانية. التقارير: حساب الأستاذ برصيد أول المدة ورصيد متحرك، ميزان المراجعة بأرصدة وحركة، وقائمة الدخل. فلاتر التاريخ ومركز التكلفة، والحساب في الأستاذ والميزان. اختيار حساب رئيسي يشمل حساباته التابعة، وفلاتر مراكز التكلفة تطابق المركز المحدد فقط. التصدير CSV متوافق مع Excel مع حماية الخلايا النصية من الصيغ؛ ليس ملف XLSX. الطباعة متاحة من التقارير.

## نسخ احتياطية وحدود النسخة

زر «تنزيل نسخة احتياطية» ينزّل ملف ZIP يحتوي accounting.json وكل المرفقات المرتبطة بالقيود. احفظه في مكان آمن؛ يحتوي بيانات مالية. الاسترجاع يحتاج استيراد الحالة والمرفقات بواسطة مسؤول قاعدة البيانات، وليس هناك زر استرجاع داخل الواجهة بعد. وتصدير التقارير وحده ليس نسخة احتياطية. يمكن أيضًا استخدام أدوات Supabase/pg_dump لنسخ قاعدة البيانات كاملة بما فيها سجل التدقيق والمستخدمون. لا تعتمد على الاستضافة المجانية لضمان نسخ احتياطي تلقائي. الحساب مشترك؛ لا يمكن نسب العمليات لمحاسب بعينه. تاريخ إنشاء القيد محفوظ، وسجل تدقيق مستقل على الخادم يسجّل وقت ونوع العملية، ويُعرض في الواجهة. لا توجد فواتير أو مخازن أو تعدد عملات أو إقفال سنة مالية تلقائي. النسخة الاحتياطية المنزّلة لا تشمل حسابات المصادقة أو سجل التدقيق السحابي؛ استخدم نسخة قاعدة البيانات الكاملة لحفظهما.

## الخصوصية

لا تُستخدم بيانات أو شعارات أو مرفقات التسجيلات المرجعية. لم تُضمّن كلمة المرور المشتركة في الملفات. تغيير كلمة المرور من لوحة Supabase يغيّرها لجميع من يستخدمون الحساب.
